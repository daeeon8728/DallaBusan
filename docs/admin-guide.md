# dallaBusan 콘텐츠 관리자

2026-11-26 사용자 요청으로 공개 사이트와 별도 관리자 화면을 제공한다. 기존 관리자 미구현 제한은 이 범위에 한해 대체한다.

## 주소와 첫 실행

```sh
npm ci
npm run admin:setup
npm run build
npm run start
```

- 공개 화면: `http://127.0.0.1:3001/`
- 관리자: `http://127.0.0.1:3001/admin` 또는 `/admin.html`
- `npm run dev`에서는 `http://127.0.0.1:5173/admin.html`을 사용한다.
- 초기 비밀번호는 `var/admin/initial-password.txt`에 한 번만 생성된다. 콘솔·Git·브라우저 저장소에 기록하지 않는다. 재실행은 이미 설정된 인증 정보를 덮어쓰지 않는다.
- 기존 `.env` API 값은 보존하며 관리자 변수만 추가한다. `.env.example`은 빈 양식이다.

## 관리할 수 있는 내용

| 메뉴 | 조작 | 공개 반영 |
| --- | --- | --- |
| 대시보드 | 원본·초안 수, 제공처 등록 가능 상태, 저장/게시 버전 확인 | 읽기 전용 |
| 코스 관리 | 신규 제작, 5개 언어 제목·소개·팁, 5개 기존 카테고리, 장소 추가·삭제·정렬·체류시간, 숨김 | 게시 후 코스 목록·상세·조합 라이브러리 |
| 상품 관리 | 승인 레지스트리의 발급 링크·사진·원가격·관찰일·다국어 제목, 관광지 관계, 신규 등록·숨김 | 게시 후 상품·연결 관광지·코스 상품 |
| 이미지·장소 | 관광지·맛집·상품·코스 사진 URL/출처/권한, 관광지·맛집 숨김 | 게시 후 해당 콘텐츠 |
| 화면 배치 | 홈 6개 영역의 순서·노출, 추천 코스 제목 5개 언어, 대표 코스 최대 6개 | 공개 홈을 새로고침하면 적용 |
| 이력·백업 | 현재 초안 JSON 내보내기·불러오기, 최근 20개 게시본을 초안으로 복원 | 복원만으로는 공개되지 않음 |

기존 데이터는 삭제하지 않는다. 상품·장소의 제거는 숨김으로 처리한다. 사진은 사용 허용 **HTTPS URL**로 바꾸며 파일 업로드·크롭 편집은 포함하지 않는다. 기존 공식 이미지 호스트와 `ADMIN_IMAGE_HOSTS`의 명시 호스트만 허용한다. 신규 호스트는 서버 설정에 등록한다.

화면 배치는 홈페이지의 `추천 코스 / 검색·여행 준비 / 특가·쿠폰 / 이달의 명소 / 상품 분류 / 상품 목록`으로 제한한다. 임의 CSS·스크립트·HTML 주입이나 모든 화면의 자유 배치 도구는 제공하지 않는다. 쿠폰 원문·제휴 레지스트리·비밀 키·내부 테마 근거·분석/광고 계정은 기존 설정·검수 경계를 유지한다.

## 초안 → 검증 → 게시

1. 입력은 브라우저 메모리에서 편집한다. 탭을 닫기 전 초안을 저장한다.
2. **초안 저장**은 별도 SQLite에만 기록한다. 공개 화면은 그대로다.
3. **검증**은 원본 지문·공개 장소·고유 ID·권한 확인·이미지 호스트·제휴 추적/원문 호스트·제공처 자격·가격 형식을 검사한다. 실제 사진 권리나 현재 판매가를 외부에서 자동 확인하는 기능은 아니다.
4. **게시하기**는 저장된 초안에 대해 같은 검증을 다시 수행하고 트랜잭션으로 공개본/이력을 갱신한다. 실패하면 이전 공개본을 유지한다. 재시작 없이 다음 API 요청에 반영되며 열린 공개 탭은 새로고침한다.
5. 두 창이 같은 버전을 수정하면 늦은 저장은 409로 차단한다. 미저장 초안을 JSON으로 보관한 후 최신 내용을 불러와 병합한다. 자동 덮어쓰기는 하지 않는다.

새 코스는 실제 공개 관광지·맛집 ID만 사용한다. 순서/좌표/이동 모드가 바뀌면 기존 도로 경로를 사용하지 않고 참고 경로를 표시한다. 사람·현장 검수 완료나 최적화를 보장하지 않는다. 신규 상품은 `managed-UUID`와 provider/external ID로 구분하며, 같은 원본 상품을 중복 등록하거나 게시 후 정체성을 바꿀 수 없다. 미승인/제한 제공처·만료 상품은 관리자도 우회하지 못한다. 모르는 가격은 빈값(null)이다.

## 인증과 영구 저장

- 소유자 1명용 비밀번호 로그인, scrypt(N=32768,r=8,p=3), 16바이트 무작위 salt.
- 무작위 세션의 해시만 SQLite에 저장. HttpOnly/SameSite=Strict, HTTPS에서는 Secure. 유휴 30분·절대 8시간, 로그아웃/재로그인 시 폐기·회전.
- 모든 쓰기는 정확한 허용 Origin과 세션별 CSRF HMAC을 요구한다. CSRF 값은 메모리에만 둔다. 로그인 실패는 IP 원문 대신 secret 기반 digest로 15분당 5회 제한하며 IP를 프록시 헤더로 신뢰하지 않는다.
- 관리자 HTML과 인증 응답은 no-store/프레임 차단을 적용한다. 관리자 HTML에는 GTM/광고 코드를 넣지 않는다.
- `var/admin/content.sqlite`는 관광지 원본 DB와 분리된다. `state/history/sessions/attempts` 테이블을 사용한다. JSON 백업에는 콘텐츠만 포함한다. SQLite 자체 백업은 정지 또는 SQLite 백업 절차로 일관된 사본을 확보하며 실행 중 파일 하나만 복사하지 않는다.

## AWS 운영

영구 디스크가 있는 단일 Node 24 프로세스에서 사용한다. `ADMIN_STORAGE_DIR`을 영구 볼륨으로 지정하고 `.env`의 `ADMIN_ALLOWED_ORIGINS`를 실제 **HTTPS Origin**(끝 `/` 없음)으로 바꾼다. HTTP는 로컬호스트만 허용한다. TLS 프록시를 두고 애플리케이션 직접 포트를 공개하지 않는다. 저장소 디렉터리와 초기 비밀번호 파일은 정적 웹 루트 밖에 보관한다. 계정 파일은 별도 비공개로 전달한다.

Vercel 함수와 `readOnlySnapshot:true`에서는 환경 변수가 있더라도 관리자 저장소를 만들지 않고 503으로 비활성화한다. 서버리스 임시 파일에 게시 내용을 저장했다고 표시하지 않는다. **현재 Vercel 사이트에 AWS 관리자 변경이 자동 동기화되지는 않는다.** 공개 사이트와 관리 API가 같은 영구 서버를 사용하거나 향후 공유 영구 저장소가 필요하다. 다중 인스턴스·다중 운영자/RBAC·2FA·임의 미디어 업로드는 별도 확장 사항이다.

## 검증 명령

```sh
npm run lint
npm run typecheck
npm run test -- --run --maxWorkers=4
npm run check:providers
npm run build
npm run test:e2e:admin
```

관리자 E2E는 별도 포트 4320·임시 디렉터리·테스트 전용 계정을 쓰며 실제 운영자 비밀번호나 DB에 접근하지 않는다. 공개 테스트는 기존 4317 대역 서버를 유지한다. 실제 게시 테스트는 테스트 DB에만 수행한다.
