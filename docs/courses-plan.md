# dallaBusan 코스 카탈로그·첫 방문 팝업 실행 계획

작성: 2026-11-24 (Asia/Seoul). 상태: **코스 아이디어 목록·상세 및 팝업 구현**. 검증 결과는 docs/proof.md의 최신 기록을 따른다. 승인 일정/추천 엔진은 미구현.


## 0. 최신 구현 요청에 따른 범위 확정

계획 작성 이후 사용자가 코스 페이지와 수정 이미지 팝업의 실제 구현을 요청했다. 아래 기존 표/검수 계획은 보존하며 이번에는 별도 상태 editorial-idea의 **40개 아이디어 미리보기**를 공개한다. 이는 운영자 승인·현장 검수·최적화된 일정의 발행과 다르다. routeCheck=pending, fieldValidation=not-performed를 표시하며 기존 내부17개 테마/승인 플래그는 바꾸지 않는다. 아래 publication=blocked와 승인 전 공개 보류는 **검증된 일정 상품으로의 발행**에 계속 적용된다.

- /courses를 관광지 검색과 맛집 사이 상단 메뉴로 추가한다. 기존 Travel inspiration은 /courses/inspiration으로 옮기며 /recommended 주소도 보존해 전환한다.
- 홈/관광지 검색의 추천 명소2개는 코스 허브로 이동한다. 공공 RecommendedService의 필터·상세·원문은 그대로 유지한다.
- 가족/데이트/맛집/dallaBusan 각10개 미리보기는 명시적 원본 ID와 지문을 검증한다. 근거가 바뀌거나 공개 제외된 정류점은 코스 전체를 보류하며 중간을 생략해 연결하지 않는다.
- 미선정 식당/휴식/식사·디저트는 일반 안내 노드로 남긴다. FO10은 디저트 미선정/불완전 아이디어로 명시한다. 수상·어린이 메뉴/시설·실시간 웨이팅·경로/이동시간·최적화를 확정하지 않는다.
- 각 장소 상세로 연결해 기존 운영시간·메뉴·제휴상품을 확인한다. 가족은 기존 공식 주변 주차 안내를 연결하며 입구 검수/실시간 빈자리로 해석하지 않는다.
- 사용자 승인 v2의 **콜라주 부분만** public 자산에서 잘라 표시한다. 수량/검수 완료처럼 보이는 시안의 인쇄 문구·버튼 대신 5개 언어 실제 HTML을 사용한다.
- 나머지 단계2~4의 메뉴/수상/현장/동선 검수는 이월이다. 현재 구현은 단계5~7의 아이디어 탐색/팝업 UX 및 그 검증이며 완성된 검증 일정40개로 보고하지 않는다.

## 1. 목표와 이번 작업 범위

외국인 방문자가 가족·연인·음식 취향·다른 부산의 모습을 기준으로 골라 쓸 수 있는 **4개 카테고리 × 10개 = 40개 편집 코스**를 만든다. 공식 영문명은 Family / Date / Food / dallaBusan Courses다. corse는 courses로 교정한다.

최신 사용자 요청은 이전 코스 기능 제외 범위에 우선한다. 계획 단계에서는 문서·이미지만 만들었으며 최신 구현 범위는 위0절이 우선한다. 다음 구현은 고정된 편집 코스부터 시작하며 AI 일정 생성·예산 엔진·내부 결제·로그인·내장 지도는 재개하지 않는다.

기준: intent.md → spec.md → plan.md → catalog-plan.md. 기존 내부 테마17개는 원문 근거로만 참조하고 humanApproval=pending / fieldValidation=not-performed / recommendationEnabled=false를 보존한다. 아래40개는 별도 신규 편집 초안이다. 기존 테마의 승인을 승계하지 않는다.

## 2. 코스 선정·공개 원칙

- ‘부산 사람만 가는 곳’, ‘관광객이 없는 곳’, ‘웨이팅 없음’, ‘요즘 가장 핫한 곳’은 확인 없는 사실 문구로 쓰지 않는다. 외국어 표기는 Local Food Trails / Another Side of Busan처럼 편집 의도를 표현한다.
- 부산 FoodService·AttractionService·RecommendedService·주차 디렉터리와 운영자 공식 안내를 결합한다. 인기 장소를 무조건 제외하지 않고, 대기·혼잡·접근성과 대체안을 안내한다.
- 맛집은 메인 식사 → 짧은 산책 → 디저트 순서를 기본으로 한다. 한 코스에 여러 끼를 강요하지 않는다. 음식 카드에는 가게의 **해당 지점**과 원본 ID를 연결한다.
- 미쉐린 별/빕 구르망/셀렉티드와 블루리본 개수·연도를 구분한다. 공식 페이지·대상 지점·선정 연도·관찰일·재검수 기한이 없으면 수상 배지를 노출하지 않는다. 로고 사용 권한은 별도 확인하고 우선 텍스트 출처 링크를 쓴다.
- 가족에게 ‘안전’, ‘알레르기 없음’, ‘유모차 가능’을 음식 종류나 거리만으로 추정하지 않는다. 계단·경사·화장실·연령/키 제한·유모차·차량 진입·어린이 메뉴를 각각 확인한다.
- 아래 화살표는 **제안 순서**다. 확정 경로·실시간 이동시간·검수 완료를 뜻하지 않는다. 시간대는 편집상 배정할 체류 범위이며 운영시간 자료가 아니다.
- 주차장 이름은 검색·검수 대상이다. 확보된 디렉터리에서 실제 입구/운영기관/시설명/좌표/요금 출처를 확인하기 전에는 예약 가능·무료·만차 여부를 표시하지 않는다.

## 4. 동선 검수·최적화 설계

1. 정확한 입구 좌표를 확인하고 권역별로 묶는다. 직선거리는 후보 선별에만 사용한다. 같은 숫자 ID도 attraction:/food:/parking:/provider 조합 namespace로 구분한다.
2. 코스는 필수2–4곳,선택 최대2곳으로 제한한다. 가족은 대형 시설1개+식사+휴식 중심,맛집은 식사1+산책/휴식1+디저트1 중심이다. 가족 하루에 롯데월드·사찰·과학관을 모두 넣지 않는다.
3. 이동모드별 실제 도로/보행/대중교통 경로와 날짜·서비스 시각·요청 출처를 저장한다. 경로 API 계약 전에는 운영자 공식 교통안내와 수동 검수로 시작하며 없는 이동시간은 null이다.
4. 코스당 최대6개 핵심 노드의 순서 후보를 비교한다. 영업시간,브레이크타임,라스트오더,예약 슬롯,일몰,아이 휴식,차량 회수,계단 회피는 비용보다 우선하는 제약이다.
5. 제약을 만족하는 후보 중 이동시간을 먼저,환승/주차 변경 횟수를 다음으로 줄인다. 출발/종료점이 바뀌면 비교를 다시 한다. ‘최적화’는 해당 후보·시각·모드 안의 비교이며 부산 전체 전역 최적을 뜻하지 않는다.
6. 점포 체류 배정값 예시: 식사60분/디저트45분/짧은 휴식20분. 이는 초기 계획 상수이며 실제 대기시간을 포함하지 않는다. 현장 대기 자료 없이는 0분으로 채우지 않는다.
7. 대기 대체는 같은 권역·비슷한 식사 용도·영업 교집합을 만족하는 별도 검수점이다. 실시간 웨이팅 연동 없이 ‘지금 덜 붐빔’이나 ‘예약 보장’을 말하지 않는다.
8. 미해결 노드는 건너뛰어 경로를 완성하지 않는다. 핵심 장소가 닫히거나 통제되면 코스 보류 또는 검수된 독립 대안으로 전환한다. 외부 지도 길찾기 링크는 확인된 고정 장소만 사용한다.

무료 OSM 타일/Leaflet은 이동시간 계산기가 아니다. 초기에는 내장 지도를 추가하지 않는다. 경로 API는 한국 보행/도로/대중교통 커버리지·상업 사용·호출 한도·키·비용을 검토한 뒤 별도 선택한다. 무료라는 이유로 공개 OSM 타일/공용 라우팅 서버에 운영 트래픽을 무제한 보내지 않는다.

## 5. 가족 주차·메뉴 상세 계약

- 기존 공식 주차 디렉터리와 공영주차장 자료를 재사용하되 서로 다른 원본 건수를 단순 합산하지 않는다. 장소와 차량 입구를 명시 연결하고 주차 후 실제 보행 접근을 확인한다.
- 코스별 주차 카드: 이름,주소,차량 입구 좌표,운영시간,유료/무료/미확인,요금 원문,자료 기준일,보행 접근 상태,운영기관/출처,외부 길찾기. 현재 빈자리와 예약 기능은 없다.
- 최대 후보3곳을 우선 검토하되 입구/운영을 모르면 미확인으로 남긴다. 시설 부설주차가 공공 디렉터리에 없으면 시설 공식 근거를 따로 저장한다. 미확보 시설의 가상 주차장/가격을 만들지 않는다.
- 아이 식당 카드: 메뉴 원문/번역,매운 양념 분리 가능 여부,알레르기 원문,유아의자,유모차 입장,화장실,예약/대기 방식,검수일. 알려지지 않으면 ‘확인 필요’. 국밥/국수/피자라는 이유로 키즈 메뉴 배지를 주지 않는다.
- 현지 후보: 이재모피자 본점(food:124),당미옥(food:2884),거대곰탕(food:2899),기장손칼국수(food:1817). 가족 적합 배지는 메뉴·공간 별도 검수 후다. 밥/면의 비매운 주문 가능,육수 알레르기,뼈·뜨거움·개인 식단을 구분한다.

## 6. 자료·검수 모델

새 config/catalog/courses.json에는 id/slug/category/localizedTexts/region/transport/start/end/stops/optionalStops/alternatives/parkingRefs/offerRelations/evidence/review/version을 둔다. 실제 JSON·타입 파일은 다음 구현 때 만든다.

각 stop은 순서·식별 namespace·명시 sourceId·입구 좌표·체류 배정·운영 조건·식사/주차/접근성 필드를 갖는다. evidence는 URL,기관,정확한 발췌,관찰일,해당 지점/필드 fingerprint,재검수 기한을 가진다. 공식 공공정보와 점포 안내·편집 판단·현장 관찰은 같은 상태로 합치지 않는다.

발행 상태: draft → source-reviewed → operator-approved → published. 현장 검증은 별도 필드이며 하지 않았으면 not-performed를 유지한다. 미확인 필수 조건·미매핑 장소·만료 근거·디저트 미선정은 공개 보류다. 현재40개는 모두 draft다.

수상·식당 영업/메뉴는 초기7일,주차/접근은30일 재검수 목표를 둔다. 이는 운영 정책 초안이며 실시간 정확도 보장은 아니다. 임시 통제/변경 발견 시 즉시 보류한다. 인력이 확보되지 않으면 갱신 기한을 임의 연장하지 않는다.

원문·사진·업체별 URL은 기존 설정 경계를 따른다. 기존402개 상품 중 같은 원본 상품/명시 장소 관계가 확인된 것만 연결하며 지역 키워드 일치만으로 포함 투어라고 표시하지 않는다. 레스토랑 정보가 예약 제휴상품이라는 뜻도 아니다. 코스 판매가·일괄 결제·가상 후기/가격은 없다.

## 8. 첫 방문 팝업 계약

시안: design/course-popup-v2-2026-11-24.png. v1은 비교 이력으로 보존한다. **v2는 음식 패널의 커피·디저트를 제거하고 칼국수/반찬만 남긴 최신안**이다. 생성 콜라주는 장소/식당 실사진이나 현장 검증 근거가 아니다.

영문 카피: dallaBusan / FIND YOUR BUSAN / Your kind of Busan. / Four ways to explore. Forty curated routes. / Family / Date / Food / dallaBusan / 10 routes / Start with a route that feels like you. / Don’t show today / Close.

‘40’와‘10’은 디자인 목표 수량이다.40개가 실제 발행되기 전 배포에서는 현재 숫자로 바꾸거나 수량 문구를 빼야 한다. 이미지의 버튼/문구는 시안이며 실제 앱에서는 텍스트/버튼을 HTML로 구현한다. 시안 전체를 클릭 가능한 이미지맵으로 배포하지 않는다. 이미지가 로드되지 않아도 제목·목적지·닫기는 작동해야 한다.

- 하단 버튼은 정확히2개: ‘Don’t show today’(하루 안 보기),‘Close’(닫기). 추가 구매 버튼·우상단 X는 넣지 않는다. 상단4개 카테고리를 선택하면 해당 /courses?category=...로 이동하며 모달은 닫는다.
- 홈 첫 진입에 공개 코스 자료가 준비된 경우에만 한 개 표시한다. API 실패·발행0개이면 미표시한다. 월간 여행지 팝업과 동시에 쌓지 않고 우선순위로1개만 선택한다.
- Close/Escape/카테고리 이동: 해당 브라우저 탭 세션 동안 재표시하지 않는다. 새 탭/새 세션의 재표시는 허용한다.
- Don’t show today: 방문자 기기의 현지 달력 날짜 자정까지 같은 사이트/브라우저에서 모든 추천 팝업을 숨긴다.24시간 타이머와 구분한다. 코스 데이터의 월간 판정/검수 시각은 Asia/Seoul을 사용하며 둘을 섞지 않는다.
- popup 전용 저장 키만 사용하고 찜/장바구니를 초기화하지 않는다. 저장 차단 시 화면은 닫되 하루 저장 성공을 주장하지 않고 현재 세션에서 억제한다. 손상 값은 다른 사용자 데이터를 지우지 않고 안전하게 무시한다.
- native dialog 또는 동등한 focus trap,Escape,초점 복귀,스크린리더 제목,44px 이상 버튼,배경 스크롤 제한.360px 화면에서 두 버튼이 읽히고 필요하면 세로로 배치한다. 이미지 alt는5개 언어로 제공한다.
- 월간 여행지 캠페인은 monthKey/명시 게시기간/유효 데이터가 필요하다. 월 종료 시 숨기거나 일반 추천으로 전환하고 공식 부산시 월간 선정처럼 표현하지 않는다.
