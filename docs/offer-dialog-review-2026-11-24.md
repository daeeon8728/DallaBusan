# 상품 상세창·관련 상품 검토 (2026-11-24)

## 사용자 요청과 화면

상품 상세창을 PC 최대1120px, 모바일 화면 너비에서16px를 제외한 크기로 확대했다. PC는 사진과 상세/예약을 나란히, 모바일은 세로로 배치한다. 창 안의 본문만 스크롤하고 상단44px 닫기 버튼은 항상 표시한다. X, Escape 또는 창 밖 여백에서 누르고 떼기로 닫는다. 본문을 누른 후 밖에서 떼는 드래그는 닫지 않는다. 열 때 배경 스크롤을 잠그고 닫으면 원래 스크롤과 상품 버튼 초점을 복구한다. 로딩/오류에서도 닫을 수 있다.

하단 관련 상품은 기존 OfferCard의 실제 사진·통화 표시·찜·장바구니·다국어를 재사용한다. 다른 상품을 선택하면 창을 중첩하지 않고 같은 창의 상단에서 새 상세를 조회한다. 이전 상품의 예약 링크를 로딩 화면에 남기지 않는다. 관련 목록 오류는 상세 예약과 분리하며 재시도할 수 있다. 5개 언어의 설명·관련 기준·빈 목록 안내를 제공한다.

## 데이터와 선정 규칙

- GET /api/offers/:id/related?locale=en: 엄격한 ID/언어/쿼리 검증, no-store, 비공개/만료 기준 상품404, 관련 상품이 없으면 빈 배열200.
- 기존 명소의 명시 검수된 related 연결을 공유하는 공개 상품을 우선한다. 나머지는 같은 category와 scope를 모두 만족하는 공개 상품으로 보완한다. 이유(shared-place/same-category)를 함께 보낸다. 이름 유사도·좌표 근접·미확인 상품을 자동 연결하지 않는다.
- 자기 자신, 만료/미승인/예약 자격 미검증 상품을 제외하고 최대6개를 반환한다. 동일 숙소의 검수 featuredGroups는 기준 상품 그룹을 제외하고 그룹당1개로 제한한다. 같은 관련도 안에서는 기존 제공처 표시 우선순위를 유지한다.
- 기존 PublicOfferDTO와 원본 ID·가격·관찰일·이미지·언어별 검증 URL을 그대로 사용한다. 같은 종류 안내이며 실제 동선/패키지 포함 장소·재고를 보증하지 않는다. 선정 기준과 판매처 조건 확인을 화면에 설명한다.
- 상품 클릭 후 상세 API를 다시 조회해 성공한 현재 DTO의 URL만 예약에 사용한다. 원본 카탈로그·공개 제외/프로모션·저장 데이터·의존성·환경 변수는 변경하지 않는다. 외부 API 호출과 신규 제휴 발급은 없다.

## 검증

단위/통합 검사는 관련도 우선순위·같은 범위·최대6개·자기 자신/비공개/만료 제외·빈 목록·5개 언어 DTO·HTTP400/404/no-store를 검사한다. 브라우저는360/768/1280px에서 확대 너비·항상 보이는 X·바깥 클릭/본문 드래그·Escape·초점/배경 스크롤 복구·동일 창 전환·로딩/오류 닫기·관련 목록 재시도·5개 언어·가로 넘침을 검사한다. 기존 장바구니/가격 검사는 상세 본문으로 범위를 지정해 관련 카드의 별도 버튼/가격과 구별한다.

명령과 결과, 대역/실제 구분, 시연 캡처는 [proof.md](proof.md)에 기록한다. 테스트에서 외부 이미지·GTM/외부 링크는 대역이며 실제 제휴 예약/결제/광고를 실행하지 않는다.
