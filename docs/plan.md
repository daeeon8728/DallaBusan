## 1. 적용 범위와 결정 기준

기준 문서는 [intent.md](intent.md), [spec.md](spec.md), [루트 AGENTS.md](../AGENTS.md)다. 이 계획은 코드가 없던 설계 단계에서 작성한 구현 계약이다. 현재는 3단계 부산 API 연동·수집까지 완료됐으며 실행 증거와 미구현 범위는 [proof.md](proof.md)를 따른다. 다음 구현 단계는 4단계 계산 엔진이다. 아래 트리는 전체 계획이므로 모든 파일과 기능이 구현됐다는 뜻은 아니다.

intent의 서비스 목적과 필수 제약을 유지하되, 최신 사용자 결정으로 구체화된 사항은 다음 표를 따른다. 기존 intent/spec는 이번에 수정하지 않는다.

| 항목 | 구현 결정 | 남은 결정 |
| --- | --- | --- |
| 지도 | Leaflet + react-leaflet + OSM. 지도 렌더링에 카드·외부 API 키 불필요 | 실제 도보·대중교통 경로 제공처와 운영 한도 |

| 사실 데이터 | 부산 AttractionService + 검수된 로컬 장소·제휴 상품 DB | 초기 권역·장소 수·번역/사진 검수 범위 |

spec의 “AI 초안”은 AI가 완성 일정을 만드는 뜻이 아니다. AI Skeleton을 검증 데이터와 서버 계산 엔진이 구체화한 초안을 의미한다. 이전 계획의 플랫폼별 직접 분기와 위젯 기능 연결은 위 제휴 결정으로 대체한다.

유지할 범위는 부산 1~7일, 숙박 포함 1인 전체 예산, 사진 중심 매거진형 UI, 모바일/PC, Google·Apple 로그인, 5개 언어·통화, 설문, 일정 생성·재계산·직접 편집·대화형 수정, 여러 여행 저장, 읽기 전용 공유·해제, 외부 예약·결제다. 관리자 화면·내부 결제·공동 편집은 제외한다.

## 2. 아키텍처와 구현 계약

### 2.1 역할과 의존성

| 계층 | 책임 | 금지할 결합 |

| React | 사진·본문·설문·키보드 조작·번역·편집 상태·변경 비교 | 비밀키 접근, 업체별 분기, Pixi 내부에 별도 원본 일정 보관 |
| Leaflet/react-leaflet | OSM 타일·마커·지도 카메라·좌표 변환 | 실제 경로/소요 시간을 제공한다고 가정 |
| PixiJS | 지도 위 선택 구간 강조·동선 시각화 | 폼·본문·접근성 UI 전체를 캔버스로 구현 |
| domain 패키지 | 스키마·순수 예산/시간 계산·후보 평가·변경 모델 | React·DB·HTTP·환경 변수·제휴 상호 의존 |
| 서버 서비스 | 검증·소유권·데이터 결합·AI 제안·저장·공유·예약 링크 해석 | 외부 원문이나 AI 결과를 검증 없이 저장/응답 |

웹은 자체 서버의 API를 호출하고 서버가 공공 API·AI·환율을 연결한다. 지도 타일만 브라우저에서 직접 요청한다. 개발은 Vite 프록시, 배포는 같은 출처의 웹/API 구성을 우선한다. serviceKey, OAuth 비밀값, AI 키, DB 연결과 추적 서명 비밀값은 서버 전용이다.

### 2.2 공공 API와 다국어

기본 서비스 주소는 `https://apis.data.go.kr/6260000/AttractionService`다. 외부 호출은 서버의 고정된 언어 허용 목록을 사용한다.

| UI locale | 엔드포인트 | 초기 기본 통화 |
| --- | --- | --- |
| ko | getAttractionKr | KRW |
| en | getAttractionEn | USD |
| ja | getAttractionJa | JPY |
| zh-CN | getAttractionZhs | CNY |
| zh-TW | getAttractionZht | TWD |

- `resultType=json`을 모든 요청에 포함하고 인증키·pageNo·numOfRows를 직렬화한다. 인증키 파라미터의 정확한 대소문자와 인코딩 방식, 호출 한도는 승인 문서와 실제 응답으로 확정한다. 키 이중 인코딩·전체 요청 URL 로그 출력을 금지한다.
- 응답을 unknown으로 받아 엔드포인트별 외피·업무 오류 코드·item 형태를 검증한다. HTTP 200이라도 오류 XML/문자열/실패 코드이면 성공으로 취급하지 않는다. 배열·단건·빈 결과는 확인한 계약에 맞춰 정규화한다.
- `LAT`/`LNG`: 빈 문자열·null·NaN을 거부하고 위도/경도 범위와 부산 권역을 검증한다. Leaflet의 위도/경도 순서와 GeoJSON을 사용할 경우의 경도/위도 순서를 경계에서 변환한다. 무효 좌표는 0으로 보정하지 않고 지도·자동 선정에서 제외한다.
- `MAIN_IMG_NORMAL`: 안전한 URL인지 검증하고 없거나 로딩 실패하면 대체 사진 영역을 사용한다. 임의 외부 URL을 서버가 무제한 프록시하지 않는다.
- `ITEMCNTNTS`: 원문을 보관하되 기본 렌더링은 텍스트로 한다. 임의 HTML 실행을 허용하지 않는다.
- `HLDY_INFO`: 휴무 원문과 검수 상태를 보존한다. 자유 텍스트를 근거 없이 영업시간·예약 가능 여부로 확정하지 않는다.
- 원본 ID, locale, 출처, 조회 시각을 보관한다. 언어 간 ID 일치 여부를 검증하고 검수된 매핑으로 canonical placeId에 연결한다. 이름만으로 병합하지 않는다.
- 언어·페이지·필터별 캐시 키, totalCount 기반 페이지 순회, 빈/중복 페이지 종료, 요청 수 상한을 구현한다. 마지막 성공 데이터와 실패 상태를 구분하고 일부 페이지 실패를 완전한 수집으로 표시하지 않는다.
- locale 전환 시 이전 요청을 취소하거나 요청 ID로 폐기한다. 번역 누락 시 대체 언어와 원문임을 표시한다. 사용자가 명시적으로 고른 통화는 언어 전환으로 덮어쓰지 않는다.

로컬 DB는 공공 API에 부족한 식당·숙소·체험, 카테고리·권역·체류 시간·구조화 영업시간·가격 단위·제휴 상품 매핑을 보완한다. 필드별 검수 출처와 일시를 기록하고 API 갱신이 수동 검수값을 덮어쓰지 않게 한다. 개발 fixture와 실제 검수 데이터를 구분하며 테스트 가격·휴무를 운영 사실로 사용하지 않는다.

### 2.3 하이브리드 생성과 변경

1. 설문을 검증하고 locale·통화·기간·숙소·선호를 정규화한다.
2. AI에 허용된 카테고리와 검수된 권역 ID 목록, 최소한의 설문 조건을 전달한다. 계정·상세 숙소 주소·공유 토큰은 보내지 않는다.
3. AI는 날짜별 카테고리 슬롯, 권역 방문 순서, 선호 가중치 등 제한된 Skeleton만 반환한다. 실제 장소 ID·명칭·가격·영업시간·좌표·예약 URL·정밀 경로·확정 시각을 생성하도록 요청하지 않는다. 알려지지 않은 필드/권역/카테고리, 과도한 슬롯 수, 여행 일수 불일치는 거부한다.
4. 서버는 검수 DB/API에서 후보를 찾고 카테고리 적합성·권역 근접성·휴무·중복·예산을 평가한다. 동일 스냅샷/Skeleton/입력에서는 점수와 placeId 동점 정렬로 재현 가능하게 선정한다. 제휴 유무 때문에 필수 장소를 제외하지 않는다.
5. RouteProvider 또는 출처가 명시된 로컬 이동 데이터로 구간 시간을 얻어 방문 순서·체류·고정 시각·활동 시간을 계산한다. 알 수 없는 이동 시간은 후속 시각에도 미확인 상태로 전파하고 확정 일정으로 표시하지 않는다.
6. BudgetService가 숙박·식비·교통·입장/체험·기타 비용을 집계한다. 후보 부족·시간 충돌·예산 초과·미확인 항목을 초안에 표시한다. 데이터가 부족하면 짧은 일정이나 대안을 제시하며 사실을 만들어 채우지 않는다.

대화 요청은 같은 제한된 카테고리/권역 선호 또는 변경 의도로 변환한다. 직접 편집·숙소 변경·대화 제안 모두 동일 계산 엔진을 호출한다. 제안에는 proposalId, baseVersion, 변경 항목, 시간·예산 차이를 담는다. 확인 후 원본 버전이 같을 때만 원자적으로 적용한다. 취소 시 변경하지 않고, 충돌 시 409와 최신 버전을 반환해 재생성/재적용을 안내한다. 오래된 경로 응답도 버전·요청 ID로 차단한다.

AI 실패 시 결정적 기본 Skeleton으로 진행할 수 있지만 대체 사용을 표시하고 재시도를 제공한다. 가짜 AI 응답이나 실제 로그인 우회는 운영 환경에서 허용하지 않는다.

### 2.4 지도·동선·화면

Leaflet의 map/pane과 좌표 변환을 기준으로 Pixi 레이어를 갱신한다. move/zoom/resize와 반응형 패널 재배치 후 크기 변화를 처리하며 화면 재진입 시 캔버스·이벤트·애니메이션을 중복 등록하지 않는다. 드래그·줌·터치를 캔버스가 가로채지 않게 한다. WebGL 실패 시 Leaflet 기본 표시와 React 목록을 유지한다.

OSM 지도 표시는 카드·외부 API 키 없이 가능하다. 지도 타일 주소와 attribution은 설정으로 관리하며 출처를 가리지 않는다. 공용 타일은 사용 정책·캐시 헤더를 따르고 대량 수집·선다운로드·오프라인 저장 기능을 만들지 않는다. 자동화 테스트는 타일을 대역으로 처리한다. 지도 렌더링 무료라는 결정은 AI·서버·OAuth·실제 경로까지 운영비가 없다는 뜻은 아니다. [OSM 공식 타일 정책](https://operations.osmfoundation.org/policies/tiles/)을 따른다.

RouteProvider는 지도와 별개다. 제공처가 미정이면 직선 연결은 “방문 순서”로만 표시하고 실제 도로 경로나 확정 이동 시간으로 표시하지 않는다. 모든 외부 키가 없어도 지도와 목록의 기본 조작이 가능해야 한다.

화면은 시작/로그인 → 단계형 설문 → 사진 중심 일정 카드·날짜 탭·예산·지도 → 직접 편집/대화 변경 비교 → 저장/공유 → 외부 예약 이동으로 구성한다. 768px 미만은 한 열·지도 전환·접이식 대화, 768~1199px는 보조 패널 축소, 1200px 이상은 일정·지도/대화 병렬 배치를 적용한다. 360px에서 가로 넘침 없이 조작 가능해야 하며 주요 터치 영역은 44×44 CSS px 이상이다.

### 2.5 계산·저장·공유

- 시간은 Asia/Seoul, 연속 1~7일, 기본 활동 09:00~21:00이다. 기본 숙박은 일수−1박이며 1일 일정은 0박이다. 실제 체크인/아웃과 고정 방문 시각이 우선하고 충돌은 숨기지 않는다.
- 기준 예산은 숙박 포함 1인 KRW다. `1 외화 = R KRW`로 환산하여 원통화·원금액·환율·조회 시각을 스냅샷으로 저장한다. 표시 통화 변경은 기준 예산을 바꾸지 않는다. 환율 갱신은 명시적 동작이며 24시간 초과 환율 사용에는 확인이 필요하다.
- 화폐는 명시적인 소수 정밀도/decimal 연산으로 처리하고 집계 중간 반올림을 피한다. 객실 1박 단가×객실 수×박수 또는 실제 객실별 합계를 인원으로 균등 배분한다. 총 숙박 상품에 박수를 재곱하지 않는다.
- 미확인 필수 비용이 있으면 확인된 소계와 미확인 항목을 분리하고 예산 이내 확정을 금지한다. 국제선·부산 도착 전 시외 이동은 기본 제외를 안내하고 기타 비용으로 추가할 수 있다. 상품 포함 식사·교통·입장료는 중복 합산하지 않는다.
- 사용자/인증 세션, 장소 원문·번역·검수값, 상품·providerId 매핑, 여행·일자·항목·숙소·비용·환율 스냅샷·버전, 공유 토큰 해시·활성 상태를 저장한다. 여행 수정과 버전 증가는 한 트랜잭션으로 처리한다.
- 소유권은 서버가 모든 읽기·쓰기에서 검사한다. 공유는 비로그인 읽기 전용 별도 DTO로 응답한다. 숙소명·주소·정밀 좌표·관련 출발/도착 경로, 계정·설문 원문·대화를 제외하고 권역만 공개한다. 원본 여행 객체 전체를 직렬화한 후 화면에서만 숨기지 않는다.
- 공유 토큰은 충분한 암호학적 난수로 발급하고 해시로 저장한다. 해제 상태를 매 요청 확인하며 재발급 시 새 토큰을 만든다. 공유 응답은 no-store와 noindex 정책을 적용한다. 복사된 정보까지 회수할 수 있다고 약속하지 않는다.
- 설문·편집 보존은 우선 현재 세션 메모리 기준이다. 영구 브라우저 저장, 대화·설문 보존 기간, 계정 삭제는 개인정보 정책 확정 후 구현 범위를 기록한다.

### 2.6 제휴사 설정과 확장 경계

UI·도메인·비즈니스 서비스는 PROVIDER_A 등의 providerId와 공통 능력만 사용한다. `if providerId === PROVIDER_A`처럼 이름을 별칭으로 바꾼 고정 분기도 핵심 로직에 넣지 않는다. 레지스트리를 순회하고 지원 상품 유형·locale·승인 상태로 선택한다. 화면의 실제 표시명도 설정에서 읽는다.

| 항목 | 관리 위치 | 규칙 |
| --- | --- | --- |
| providerId, displayName, 상품 유형, locale, enabled/approvalStatus | 서버가 읽는 providers 설정 | 표시명·상호 변경만으로 컴포넌트/계산 로직 변경 불필요 |
| allowedHosts, baseUrl/승인 링크 템플릿, 추적 파라미터 매핑 | providers 설정 | 임의 목적지 금지. 계약으로 확인한 규격만 허용 |
| partnerId·tracking 값·서명 비밀값 | 서버 환경 변수/비밀 관리 | 설정에는 env 참조 이름만 기록. 브라우저 환경 변수로 주입 금지 |
| localProductId ↔ providerId ↔ externalProductId | 로컬 상품 DB | 장소명 추정 매칭 금지. 승인된 상품 매핑 사용 |
| WidgetProvider | 인터페이스 파일 | 실행 구현·스크립트·SDK·도메인 등록 작업 없음 |

예정 환경 변수는 AFFILIATE_CONFIG_PATH, PROVIDER_A_PARTNER_ID, PROVIDER_A_TRACKING_CODE 등이다. .env.example에는 빈 값/설명만 둔다. 파트너 ID나 추적 값이 최종 승인 URL에 나타나는 규격은 있을 수 있으나, 서명 비밀값·설정 전체·계정 정보는 공개 DTO에 포함하지 않는다.

링크 해석은 offerId와 검증된 설정/DB 매핑으로 수행한다. 브라우저가 임의 url을 보내면 그대로 리다이렉트하는 API를 만들지 않는다. 서버에서 HTTPS·정확한 허용 호스트·필수 값·승인 상태를 확인하고 안전한 URL만 반환한다. 새 창은 noopener/noreferrer와 제휴 표기를 적용한다. 비승인·설정 누락·상품 미매핑은 비활성 사유를 표시하며 임의 검색 URL·추적 코드를 합성하지 않는다. 실제 예약·결제·재고 확정은 모두 외부에서 이뤄진다.

### 2.7 실패·설정 상태

서비스별 상태를 configured/unconfigured/degraded로 구분한다. 선택적 제공처 미설정은 전체 앱 시작을 막지 않되 실제로 성공한 것처럼 보이지 않게 한다. 운영 인증·세션 같은 필수 보안 설정 누락은 안전하게 시작을 거부한다. 테스트용 로그인은 테스트 환경에서만 사용하고 운영 빌드의 우회 경로로 남기지 않는다.

외부 읽기 요청은 타임아웃과 호출 제한을 설정한다. 초기 기본값은 10초, 일시적 네트워크/5xx 오류의 자동 재시도는 최대 1회로 하고 제공처별 조정 가능하게 한다. 429는 Retry-After와 한도를 존중하고 인증/스키마 오류는 자동 반복하지 않는다. 저장·제안 적용은 idempotency key와 버전 검사 없이 자동 재전송하지 않는다. 로그는 요청 ID·상태·소요 시간만 우선 기록하고 토큰·키·대화 원문은 제외한다.

## 5. 검증 방법 (Proof)

### 5.1 실행 명령 계약

루트 스크립트는 아래 이름을 계약으로 한다. 최초 lockfile 생성은 npm install로 수행하고 이후 재현 설치는 npm ci를 사용한다. 현재 1~3단계 검증 결과는 proof.md를 따른다. DB·수집 명령은 실제 구현됐으며 수집의 partial/failed는 종료 코드 1이다. Windows PowerShell에서 npm.ps1 정책 문제만 발생하면 같은 명령의 npm.cmd를 사용한다.

| 명령 | 확인할 결과 |
| --- | --- |
| npm ci | 잠금 버전 설치. lockfile 임의 변경 없음 |
| npm run dev | web 5173, server 3001 기본 포트로 실행. 포트는 설정 가능 |
| npm run db:migrate / npm run db:seed | 선택된 개발/테스트 DB에 마이그레이션·검수 seed 적용 |
| npm run data:import -- --locale=ko | 승인 키로 해당 locale 수집. 실제 호출이므로 별도 수행 |
| npm run lint | 전체 소스 정적 검사 |
| npm run typecheck | web/server/domain strict 타입 검사 |
| npm run test -- --run | Vitest 단위·서버 통합 테스트 1회 실행 |
| npm run check:providers | 제휴 경계·업체 리터럴/직접 환경 접근 규칙 검사 |
| npm run build | domain → server/web 의존 순서로 실제 컴파일·번들 생성 |
| npm run test:e2e | Playwright가 테스트 DB·테스트 서버로 사용자 흐름 확인 |
| npm run start | 빌드된 서버와 web 산출물 실행, 실제 산출물 smoke 확인 |

루트 test는 단일 Vitest 실행으로 대상 테스트를 수집하고 E2E를 제외한다. build는 의도적으로 타입 오류를 숨기는 옵션이나 빈 성공 스크립트로 대체하지 않는다. domain 출력 후 server/web가 참조 가능해야 하고 Node ESM·경로 alias가 빌드 산출물에서도 해석돼야 한다. 예상 산출물은 packages/domain/dist, apps/server/dist, apps/web/dist다. start는 개발 TS 파일이 아닌 이 산출물을 사용한다.

검사 실패 시 원인을 수정하고 실패한 검사 및 영향받은 검사를 재실행한다. build가 실패하면 원인을 해결해 종료 코드 0을 확인할 때까지 수정·재빌드한다. 자격증명 없이도 build는 가능하게 설계하며 자격증명을 요구하는 실연동 성공과 구분한다.

### 5.2 수용 시나리오와 관찰할 증거

| 범위 | 터미널/브라우저 검증 | 통과 기준 |
| --- | --- | --- |
| API 5개 언어 | fixture 계약 검사·서버 outbound 요청 가로채기 | locale별 정확한 endpoint와 resultType=json. 잘못된 locale·XML 오류·빈/단건/중복 페이지·키 오류 처리 |
| 수치·경계 | 단위 검사 | 1/7일 허용, 0/8일 거부, 1일 0박, 3일 기본 2박. 객실 2개×1박 100,000원×2박÷4명=1인 100,000원. 총액 상품 재곱 없음 |
| 환율·예산 | 단위 검사·예산 패널 | 시험 환율로 환산·반올림·24시간 초과 확인을 검증. 미확인 항목은 0원/예산 충족으로 표시하지 않음 |
| AI 역할 제한 | malformed/추가 필드/미등록 권역 응답 주입 | AI 장소·가격·URL을 버리고 허용 스키마만 사용. 같은 Skeleton/스냅샷은 같은 계산 결과 |

### 5.3 증거와 완료 보고

구현 시 docs/proof.md에 실행 시각, 변경 버전, Node/npm 버전, 명령·종료 코드, 테스트 수·실패 원인/수정 결과, 캡처 위치, 실제/대역/미설정 구분을 기록한다. 비밀키·토큰·개인정보는 기록하지 않는다.

“코드 검증 완료”는 실제 구현과 해당 자동 검사·빌드 성공을 뜻한다. “출시 준비 완료”에는 실제 OAuth/API·제휴 승인·경로/환율·데이터 검수·배포/백업·개인정보 정책의 검증도 필요하다. 빌드 성공만으로 후자를 선언하지 않는다. 문서만 변경하는 작업은 구조·정합성·변경 범위를 확인하고, 구현 단계의 build 성공은 실제 실행 결과에 근거해 proof.md에 기록한다.

## 2026-11-15 테마 코스 템플릿·장소 연결 구현

사용자 승인 범위는 화면 없이 내부 코스 자료를 구조화하고 원문 방문 순서를 검증하는 단계다. 상세 결과는 [검수 보고서](theme-route-review-2026-11-14.md), 계약·CLI는 [운영 절차](operations.md)의 최신 절을 따른다. 기존 공공 소개/상품 화면과 공개 API는 그대로 유지한다.

테마 원본402그룹/1,191언어 레코드 전체의 coverage를 기록하고, 16개 원본 그룹에서17개 템플릿을 선별했다. 원문 순서 확인15개, 장소까지 확인한 부분 템플릿1개, 검토 대기16개, 연속 구간8개다. 관광지 연결35회·맛집 방문 연결2회, 별도 맛집 후보19개(원문 언급2/직선1km 후보17)를 확인했다. 연결 횟수는 고유 물리 장소 수가 아니다. 미선별386그룹과 미해결43개 방문 노드를 숨기지 않는다.

모든 템플릿은 assistant-source-evidence의 원문 대조이며 humanApproval=pending, fieldValidation=not-performed, recommendationEnabled=false다. 원문·장소 fingerprint 변경 시 기존 승인을 재사용하지 않는다. 불명확한 별칭·복합 장소 좌표·본관/별관은 보류한다. 맛집 후보는 방문 순서에 삽입하지 않으며 직선거리를 이동시간으로 바꾸지 않는다. 사람·현장 검수, 주차 후보, 실제 길찾기, 자동 추천·UI는 후속 범위다.


## 2026-11-18 기기별 찜하기·주차 공개자료

최신 사용자 요청으로 관광지·맛집·상품의 로그인 없는 찜을 추가한다. /saved에서 종류별 필터·삭제·새로고침 후 복원·다중 탭 동기화·현재 언어/공개 상태 재조회가 가능하다. localStorage에는 version1/중립 종류/ID/저장 당시 이름/시각만 저장하며 예약 URL·가격·계정/키는 저장하지 않는다. 최대200개, 화면당12개 조회로 제한한다. 저장 차단/공간 부족은 성공으로 표시하지 않고 손상 데이터는 동의 없는 초기화를 하지 않는다.

공식 전국 표준 주차 자료18,994행 전체에서 부산653행을 선별해641건을 공개 디렉터리에 연결했다(유료603/자료상 무료37/요금 미확인1, 공영411/민영230). 중복 식별12행은 보류하고 원본은 유지한다. 모든 부산 실재 주차장/최신 영업/실시간 빈자리 확보를 의미하지 않는다. 자세한 범위·구별 집계·보류 사유는 [수집 보고서](parking-directory-2026-11-18.md)를 따른다.

주차 단독 페이지·지도/AI/코스 엔진은 추가하지 않는다. 기존 검색 페이지의 주차 검색/필터와 관광지·맛집 상세의 주변 주차 펼침 영역으로 제공한다. 직선1km 이내 최대3건이며 보행경로나 입구/주차 가능을 보장하지 않는다. 기존615행 주차 이력은 합산하지 않고 보존한다. 갱신 명령은 data:parking-directory:refresh/check이며 키 없이 공식 공개 다운로드를 사용한다.


## 2026-11-18 상품 장바구니·참고 합계

사용자 요청으로 언어 선택창 옆 장바구니 진입(/cart)과 상품 카드·상품 상세·찜한 상품의 담기 버튼을 추가한다. 로그인 없이 같은 브라우저/주소에서100개 상품을 보관하며 수량1~99와 삭제를 지원한다. 반복 담기는 중복 생성/수량 자동 증가 없이 처리한다. 저장 값은 상품 ID·중립 providerId·externalId·이름·수량·시각뿐이며 가격/통화/예약 URL을 저장하지 않는다. 찜 저장 키와 분리한다.

장바구니를 열거나 새로고침/명시적 다시 확인 시 기존 검증된 공개 상품 API에서 현재 언어·상품 정체성·가격을 조회한다. ID/provider/externalId가 달라지거나 미공개/만료/실패이면 예약 URL·금액을 합계에서 제외하고 항목은 보존한다. 조회는 동시6건으로 제한하며 이전 요청을 취소하고 늦은 응답을 차단한다.

현재 가격 계약에는 실시간 최저가·옵션별 최소가 근거가 없어 UI는 표시 가격 기준 참고 합계라고 안내한다. 등록된 원통화 참고가×사용자가 선택한 수량을 정확한 십진수(BigInt)로 합산하고 다른 통화는 나눠 표시한다. 원화 자동 환산·인원/박수 자동 곱셈·최종 결제·예산/AI 엔진을 추가하지 않는다. 가격 없는 상품은0원으로 계산하지 않고 미확인 개수를 별도 안내한다. 모르는 가격/확인 불가 항목이 있으면 부분 합계임을 표시한다. 모든 가격이 없으면 금액 합계를 만들지 않는다. 예약은 각각의 기존 외부 제휴 링크로 이동한다.


## 2026-11-19 언어별 표시 통화 환산 (최신 요청)

이 절은 이전의 표시 환산 제외 규칙에 우선한다. 상품 카드·상세·관광지 연관 상품·찜한 상품·장바구니는 ko→KRW, en→USD, ja→JPY, zh-CN→CNY, zh-TW→TWD로 표시한다. 영어/번체가 특정 국적을 확정하는 뜻은 아니며 각각 USD/대만 TWD를 기본값으로 선택했다. 원본 금액·통화·가격 관찰일·검증된 예약 URL은 변경하지 않는다. 환산가에 ≈와 원래 가격을 함께 표시하고 환율 제공일 범위·출처·참고가/외부 최종 확인 안내를 제공한다. 같은 통화는 환산 없이 원금액을 유지한다.

서버 고정 주소 https://api.frankfurter.dev/v2/rates?base=USD&quotes=KRW,JPY,CNY,TWD 를 사용한다. API 키가 필요 없으므로 .env 기존 값과 lockfile/의존성을 변경하지 않는다.
