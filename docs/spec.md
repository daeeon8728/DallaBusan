## Requirements

2026-11-10 사용자 변경 지시를 반영한다. 과거 일정 서비스 요구는 현재 적용하지 않는다.

- 부산 관련 티켓·투어·패키지·체험·요트·교통·숙소 카탈로그를 제공한다.
- 검색, 카테고리/판매처 필터, 페이지 이동, 결과 수, 빈 결과와 초기화, 상품 상세를 제공한다.
- 모든 공개 상품은 검수한 소스와 실제 제휴 URL/승인 템플릿을 가진다. 미승인·잘못된 호스트·만료 상품은 예약 링크로 노출하지 않는다.
- 제휴 표시, 새 창 외부 이동, 가격·날짜·옵션·재고 재확인을 안내한다. 예약/결제/환불은 외부 판매처가 처리한다.
- 방문자 로그인 없이 읽기 전용으로 이용한다. AI·예산·여행 일정 기능은 제외한다.
- 한국어·영어·일본어·간체·번체 UI를 지원한다. 제목이 번역되지 않았으면 원문과 언어를 표시한다.
- 모바일/PC·키보드·44px 조작 영역·이미지 실패 대체·오류 재시도를 지원한다.

## Design

### 화면

브랜드/상단 언어 선택 → 부산 사진과 검색 → 카테고리 바로가기 → 여행 테마 소개 → 판매처/카테고리 필터와 상품 그리드 → 상세 dialog → 외부 예약 순서다. 네이비·블루와 따뜻한 배경, 큰 사진·여백을 사용한다. 360px 1열, 중간 화면 2열, 데스크톱 4열이다.

상품 카드는 실제 제목, 원문 언어, 분류/여행 범위, 판매처, 참고가 또는 가격 확인, 상세 동작을 표시한다. 공식 제휴 이미지가 없으면 사용권이 확인된 부산 대표 이미지임을 명시한다. 상세 dialog는 Escape와 닫기 버튼을 지원하고 원래 조작 위치로 포커스를 돌린다.

### 핵심 규칙

- 상품의 실제 명소/판매 옵션을 이름만으로 병합하지 않는다. provider/externalId별로 구분한다.
- 부산 내·부산 출발·부산 도착·지역 복합 상품을 구분한다. 무관한 해외 추천·일반 배송 상품은 제외하고 검수 기록을 남긴다.
- 가격은 원통화·관찰일을 보존한 참고가다. 통화 환산·사용자 예산·인원 곱셈·확정 재고 판정은 없다. 가격이 없으면 0원이 아닌 외부 확인 상태다.
- 링크는 HTTPS·정확한 호스트·승인 상태·필수 추적 파라미터·중첩 목적지를 검증한다. 사용자 URL을 받는 오픈 리디렉트 API는 만들지 않는다.
- UI는 최소 공개 DTO만 받고 업체 이름/도메인/추적 값을 하드코딩하지 않는다. API 키·전체 설정·계정 정보는 응답에 넣지 않는다.
- 데이터 로딩은 취소/요청 순서 검사를 적용해 이전 응답이 최신 검색/언어를 덮어쓰지 못하게 한다. 실패 시 입력·마지막 성공 목록을 보존한다.
- 오래된 가격을 새 가격으로 표시하지 않는다. 상품의 제목에 명백한 지난 기간이 확인된 경우 공개 대상에서 제외한다. 날짜가 불명확하면 외부 확인을 안내한다.

## 2026-11-11 검색·이달의 관광명소 확장 명세

- /search는 독립 진입·새로고침 가능한 상품 검색 페이지다. 검색어·판매처·분류·범위·페이지·locale을 URL에서 복원하며 브라우저 뒤로/앞으로 이동을 지원한다.
- 홈과 검색에 추천 배너를 제공한다. 설정한 월과 Asia/Seoul 현재 월이 같을 때만 '이달의 관광명소'로 표시한다. 월이 지나면 '부산 명소 가이드'로 표시하며 공식 선정·시즌 행사·실시간 영업이라고 주장하지 않는다.
- /places/:slug에서 명소 이름·소개 발췌·주소·휴무 원문·출처·수집일·검수일을 표시한다. 5개 언어를 지원하며 없는 번역은 원문 대체를 명시한다.
- '투어·패키지 / 관련 시설 티켓 / 체험 / 주변 권역 숙소'를 구분한다. 검수한 offerId 매핑만 사용하고 예약 링크·가격은 기존 OfferService의 검증된 DTO를 재사용한다. 매칭되지 않았거나 비활성·만료된 상품은 노출하지 않는다.
- 티켓은 관련 유료 시설의 상품이며 마을·해변 자체의 입장료라는 뜻이 아니다. 주변 숙소는 권역과 이동 필요 안내를 표시하며 도보 시간·거리·객실 재고를 임의로 만들지 않는다.
- 최초 공개는 감천문화마을과 광안리해수욕장이다. 실제 API 레코드 365/377의 5개 언어 스냅샷을 명시적으로 선별했으며 전체 다국어 명소 DB의 검수 완료를 의미하지 않는다.
- 사진은 기존 사용권이 확인된 해당 명소 사진을 재사용하고 credit을 표시한다. 공공 API의 미승인 원본 사진을 자동 노출하지 않는다.
- API 실패·없는 명소·빈 관련 상품을 구분하고 재시도/검색 복귀를 제공한다. 실패 시 같은 요청의 마지막 성공 정보는 보존하며 이전 언어/다른 명소의 늦은 응답을 현재 화면에 적용하지 않는다.

## 전체 관광정보 통합 검색 (2026-11-11, 최신 계약)

- /search에서 상품 검색어와 같은 검색어로 전체 공공 관광정보도 조회한다. 관광정보는 이름·검수 별칭·다국어 소개·지역을 검색하며 6건씩 페이지 이동하고 '연결 상품이 있는 명소만' 필터를 제공한다.
- 원본 ID 그룹 220개, 언어 레코드 1,044개 전체를 반영한다. 이름만으로 다국어를 묶지 않고 같은 원본 ID·원제목·비어 있지 않은 좌표 일치를 함께 검증했다. 서로 다른 ID의 유사/중복 관광 소개는 유지한다. 220은 중복 제거한 물리 명소 수가 아니다.
- API의 ADDR1을 안전하게 파싱한다. 주소 213건을 제공하고 외국어 전용 7개 그룹의 미확인 주소는 원문 권역 및 공식 정보 확인 상태로 표시한다.
- 명소 이름/검수 별칭 검색 시 해당 명소에 연결된 상품 ID를 상품 검색 결과에도 합친다. 예: Gamcheon + 숙소 분류 → 기존 남포동 권역 숙소 상품. 상품명 검색과 합집합이며 판매처·분류·여행 범위 필터와 기존 링크 검증은 모두 적용한다.
- 현재 관광정보 25개와 기존 상품 117개의 관계 190개를 명시적 ID로 연결한다. 상품 없는 관광정보는 검색·소개를 제공하고 빈 예약 그룹으로 안내한다. 미연결 상품 186개는 기존 상품 검색에서 계속 찾을 수 있다.
- 주소/사진/운영 검수 여부를 임의로 올리지 않는다. 편집 가이드 2개를 제외한 자료는 공공 원문 안내 상태로 표시하고 검수일은 null이다. 사용권이 확인되지 않은 명소 사진 218개는 이미지 준비 중으로 표시한다.
- data:import는 원본 DB 수집, data:publish는 검증된 관계 설정과 원본을 공개용 스냅샷으로 내보내는 단계다. API 호출은 서버 CLI에 한정하며 방문자의 검색은 로컬 스냅샷만 읽는다. 정기 스케줄러·상품 API 실시간 동기화는 추가하지 않는다.

## 2026-11-12 맛집·추천여행 검색 명세

- 상단 /food(맛집 찾기), /recommended(추천여행) 메뉴와 /food/:id, /recommended/:id 상세를 제공한다. 목록은 12건씩 검색·페이지 이동하고 locale/q/district/category/page를 URL에서 복원한다. 이름·한국어 원제목·메뉴·주소·지역·소개를 검색하며 추천여행은 원문 테마도 필터링한다.
- FoodService/getFoodKr·En·Ja·Zhs·Zht, RecommendedService/getRecommendedKr·En·Ja·Zhs·Zht로 언어별 전체 페이지를 서버 CLI에서 수집한다. resultType=json, ServiceKey, pageNo, numOfRows를 전송한다. 방문자 조회는 검증된 로컬 수집본만 읽는다. 키는 .env의 FOOD_SERVICE_KEY/RECOMMENDED_SERVICE_KEY에만 저장하며 클라이언트·공개 JSON·로그에 넣지 않는다.
- 원본 UC_SEQ는 서비스 종류로 구분한다. 언어별 중복 ID·전체 건수·페이지 번호·원제목/좌표 충돌을 검증한다. 서로 다른 ID나 두 서비스의 같은 ID를 합치지 않는다. 한 언어라도 불완전하면 전체 발행을 중단해 마지막 성공 파일을 보존한다.
- 선택 언어가 제공하는 목록만 표시하고 언어별 전체 수를 안내한다. 상세에 선택 언어가 없고 같은 서비스/ID의 한국어가 있으면 원문 대체를 표시한다. 해당 한국어도 없으면 명시적 없음 화면을 표시한다. 자동 번역·영업 중·평점·확정 메뉴 가격을 생성하지 않는다.
- 대표메뉴와 운영시간/요금은 원문 텍스트이며 비어 있으면 공공 정보 미등록으로 표시한다. 외부 HTML/스크립트는 텍스트 처리하고 이미지/홈페이지는 비밀정보 없는 HTTPS를 검사한다. 사진은 API가 지정한 Visit Busan 콘텐츠 이미지만 사용하고 출처·이용허락·수집일을 안내한다. 사진 실패는 중립 대체 화면이다.
- 공개 API: GET /api/guides/:kind 및 GET /api/guides/:kind/:id. 엄격한 입력 검증(400), 없는 항목(404), 미수집 서비스(503)를 구분한다. 사용자 URL·API 엔드포인트·키를 입력받지 않는다. 공개 DTO에서 좌표와 비밀 설정을 제외한다.
- 모바일 1열/태블릿 2열/PC 3열, 키보드와 44px 조작 영역, 오래된 요청 취소, 검색 입력/마지막 성공 목록 유지·재시도, 직접 진입·새로고침·뒤로/앞으로·5개 언어 전환을 지원한다. 관광정보와 제휴 상품을 자동 연결하거나 예약 기능을 추가하지 않는다.

## 2026-11-14 공영주차장 수집·정규화 계약

공영주차장 CLI는 API 전체 페이지를 수집하고 관리기관명+관리번호를 sourceKey로 보존한다. 원본 mgntNum/sourceId는 변경하지 않는다. 식별 정보 누락·동일 복합키 충돌은 모든 해당 행을 원본과 함께 격리한다. 정규화된 필드·원본·페이지 해시·품질 보고서의 재계산 일치를 확인한 후 config/catalog/parking.json을 원자 교체한다. 주차 페이지/공개 API/추천 동작은 없다. 좌표와 주소 키·운영시간·요금·잔여면수·기준일의 해석은 tourism-parking-plan 최신 구현 절을 따른다.


## 2026-11-15 테마 코스 템플릿·장소 연결 구현

사용자 승인 범위는 화면 없이 내부 코스 자료를 구조화하고 원문 방문 순서를 검증하는 단계다. 상세 결과는 [검수 보고서](theme-route-review-2026-11-14.md), 계약·CLI는 [운영 절차](operations.md)의 최신 절을 따른다. 기존 공공 소개/상품 화면과 공개 API는 그대로 유지한다.

테마 원본402그룹/1,191언어 레코드 전체의 coverage를 기록하고, 16개 원본 그룹에서17개 템플릿을 선별했다. 원문 순서 확인15개, 장소까지 확인한 부분 템플릿1개, 검토 대기16개, 연속 구간8개다. 관광지 연결35회·맛집 방문 연결2회, 별도 맛집 후보19개(원문 언급2/직선1km 후보17)를 확인했다. 연결 횟수는 고유 물리 장소 수가 아니다. 미선별386그룹과 미해결43개 방문 노드를 숨기지 않는다.

모든 템플릿은 assistant-source-evidence의 원문 대조이며 humanApproval=pending, fieldValidation=not-performed, recommendationEnabled=false다. 원문·장소 fingerprint 변경 시 기존 승인을 재사용하지 않는다. 불명확한 별칭·복합 장소 좌표·본관/별관은 보류한다. 맛집 후보는 방문 순서에 삽입하지 않으며 직선거리를 이동시간으로 바꾸지 않는다. 사람·현장 검수, 주차 후보, 실제 길찾기, 자동 추천·UI는 후속 범위다.
